前端加载优化以资源传输量、重复请求数和内容出现时间验收，保留现有主题布局和字体字形，原始宣传素材留存，页面使用压缩版本。

首次加载站点设置通过 Nuxt payload 复用；帖子由首页一个入口加载，首次进入及切换筛选立即发起，搜索输入保留 200ms 防抖。个人收藏和消息在身份确认后并行加载，不延长全站启动提示。话题的并发读取在当前 Nuxt 实例内合并，修改帖子后的强制刷新保留版本保护。

登录和发帖弹窗的壳始终存在，内部表单和编辑器首次打开时才挂载。字体保留原有完整 Unicode 子集，额外生成同字形、同可变字重的小型界面子集；两组 unicode-range 互补，新增界面文字或动态内容仍能从原字体获得字形。

字体维护需要 Python 3.10+ 和 `scripts/font-tools-requirements.txt` 中的依赖。更新原字体后依次执行：

```text
node scripts/vendor-fonts.mjs
python scripts/subset-ui-fonts.py
```

仅更新界面文字时可单独执行第二条。原字体与许可证须保留；脚本会检查子集的字符覆盖和可变字重轴，并更新 fonts.css、字体清单及带内容哈希的 WOFF2 文件。生产构建和用户访问不需要 Python，也不访问外部字体服务。

界面图片维护：

```text
node scripts/prepare-ui-assets.mjs
node scripts/sync-award-rules.mjs
```

脚本保留 Logo PNG 和原背景图片，生成 128/256/512px WebP Logo 以及桌面、移动端背景。二维码继续使用原始图片，避免改变识别与保存结果。

验收包括 `tests/feed-client.test.mjs` 中的话题请求合并和强制刷新，以及 `e2e/home-loading.spec.ts` 的首访请求计数、延迟挂载和搜索行为。登录恢复、账户隔离、发帖与草稿、宣传二维码和站点背景沿用既有回归测试。浏览器测量应使用相同视口和数据，区分空缓存与重复访问；链接预取流量计入总量时应明确标记。

**本轮对照结果**

以下为本地生产构建、相同匿名首页内容、空浏览器缓存的对照。JSON 接口由独立测试服务统一增加 300ms 延迟；配图使用相同固定测试图片。传输量包含响应头和链接预取。本地静态服务与线上 CDN 压缩口径不同，不能将这些数值与此前线上 3.39MB 直接计算降幅。

| 指标 | 修改前构建 | 优化后构建 |
| --- | ---: | ---: |
| 首访总传输量 | 4.20MB | 2.83MB（减少约 33%） |
| 字体传输量 | 1.75MB | 1.22MB（减少约 30%） |
| 帖子列表进入 DOM | 1.59 秒 | 1.20 秒 |
| 浏览器重复请求站点设置 | 1 次 | 0 次 |
| 帖子列表请求 | 2 次 | 1 次 |
| 话题请求 | 2 次 | 1 次 |
| 字体请求数 | 28 | 37 |
| 全部站点 HTTP 请求数 | 90 | 103 |

小型字体子集增加了文件数量，但减少了字节数；本轮没有达到字体 500KB 和本地首访 1.5MB 的预期目标。完整字符补集、链接预取和本地未使用 CDN 压缩的 JS/CSS 仍占据传输量。FCP 的单次样本为 1.04 与 1.10 秒，不能宣称所有首屏指标均改善；帖子 DOM 时间也不等于实际绘制或用户滚动到帖子的位置。部署后应在真实运营商网络下重新验证缓存与传输量。

社团 Logo 原图为 690,906 字节，新增 128/256/512px WebP 分别为 8,848/24,698/68,740 字节；首页选择小尺寸版本。桌面背景由 421,360 降为 255,318 字节，移动版由 159,040 降为 101,388 字节。二维码原图及其保存文件哈希保持不变。

**首批帖子 SSR 的独立实验**

同样的 300ms 接口延迟下，另建临时实验构建，仅将首批帖子移至 SSR 并复用 payload。与当前优化版相比，HTML 首字节从约 0.49 增至 0.79 秒，FCP 从约 0.98 增至 1.31 秒，帖子 DOM 从约 1.11 提前至 0.99 秒。增加服务端等待使整体首屏更晚，本轮没有采用这一 SSR 改动。实验源码和结果仅保存在忽略的 `.data/ssr-candidate` 与 `.data/visual-checks/performance` 中，不进入正式构建。

**2026-11-14：作品书架与十二橙器加载优化**

书架继续使用 SSR 和每页 24 部的浏览器分页。新增 `/api/works?view=summary`，仅省略列表不用的 `bangumi.summary`，成员维护的 `description`、排序、评分、标签、添加人和荣誉保持完整；默认目录、作品详情和管理接口仍返回完整资料。

书架与活动页通过 `useWorkCatalog` 共用当前浏览器标签页的 60 秒目录缓存，SSR 请求之间隔离。到期、手动刷新及添加、导入、编辑、更换封面后的失效均会重新加载，失败不进入有效缓存。Nuxt 会保留成功的 AsyncData 条目，因此非 lazy 导航额外检查缓存期限，不能仅依赖 `getCachedData` 实现过期。

活动页的目录改为独立的非阻塞请求，与活动初始化并行。打开提名窗口复用新鲜目录，已有目录请求尚未完成时不重新启动请求，窗口内显示加载或失败重试状态。活动定时器同步注册并在离开页面时清理，避免初始化尚未完成时离开、随后才创建定时器的残留。

可见页面每 15 秒刷新当前活动详情，列表每 60 秒重新校验；隐藏标签页和已归档活动暂停网络轮询。相同账号、相同活动的重叠读取合并，写入后的刷新强制获取新结果，并用版本及账号检查阻止旧响应覆盖新状态。

第一届归档的静态正文不再等待届次导航接口。归档封面使用稳定作品编号 `coverRank` 匹配响应式资源，不能把获奖名次当作作品编号；上传封面和 Bangumi 封面保持原有优先级。前三张仍主动加载，其余封面保持懒加载，手机根据实际约 120px 的封面槽位选择资源。

使用此前采集的同一份 70 部作品数据，目录 JSON 从 223,338 降到 136,289 字节，减少约 39%。本地生产构建、独立浏览器缓存、DPR 1 下滚动加载第一届全部 12 张封面，原始文件合计 5,026,358 字节，优化后 1440px 桌面选择的文件合计 339,056 字节，390px 手机为 92,450 字节。这里只比较封面资源文件大小；高 DPR、已有浏览器缓存或自定义封面会改变实际选择，不能当作全站流量或线上加载时间的保证。书架装饰图在本次桌面测试中从 600px 改选 320px。

浏览器回归覆盖 SSR 复用、跨页共享与到期、失败重试、慢目录不阻塞活动、加载中离开、详情轮询与归档停止、静态归档和响应式封面，以及原有提名、投票、加赛、管理、荣誉及分页流程。原始记录和截图在忽略的 `.data/page-loading-audit`。本轮修改文件的格式检查通过；全库仍有 11 个未修改文件的既有格式警告。
