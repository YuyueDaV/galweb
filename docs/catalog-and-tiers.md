# 作品书库、Bangumi 与 Tier 榜单

书架 `/works` 从本机或服务器 MySQL 中读取作品，同时为所有访客提供 Bangumi 游戏条目搜索。访客可查看封面、发售日期、外部评分和原站链接；所有注册用户可通过 `/works/new` 搜索并添加作品，也可手动填写资料、上传自己的封面。搜索不会自动写入书库。

添加人由服务端记录，书架与作品详情显示其当前昵称；注销后显示“已注销用户”，历史作品继续保留。旧作品未记录添加人的，不补造署名。用户可以更换本人所添加作品的封面，管理员可维护任意作品封面；上传图片须属于当前账号且未被隐藏。修改封面携带作品版本号，避免覆盖他人的更新。

公共书库按 Bangumi 条目编号及规范化后的名称、原名查重，兼容大小写、全角字符、空格和标点差异；并发添加在同一书库事务锁内校验，重复请求返回已有作品提示。个人榜私有作品首次加入公共书库时复用原编号。不同 Bangumi 编号的同名作品需核对后由管理员处理，不能重复创建。

## 管理入口

- `/admin/works`：搜索 Bangumi、直接收录新作品、编辑社团文案和更新外部资料。顶部“手动添加”进入作品添加页面；选择已有作品后，可预览和上传封面，也可恢复默认封面。封面选择后立即保存，保留当前尚未保存的文字编辑。
- `/admin/tiers`：维护共同投票榜的分层与作品池，并审核用户个人榜。
- `/tiers/mine`：所有注册用户可制作、保存及发布自己的个人 Tier 榜，支持直接从 Bangumi 添加作品。
- `/tiers`：所有访客可浏览共同投票榜与用户个人榜，并按类型筛选；个人榜展示作者和完整排列。

书库编号是稳定的作品 ID。原十二部作品保留编号和历史排名，新增作品不会被当作十二橙器第十三名。关联原作品时保留原有书单、讨论及社团推荐语；外部原文名、简介、评分、标签、封面和资料更新时间单独保存在作品的 `bangumi` 字段中。

搜索结果直接作为新作品收录，不提供关联已有作品的下拉选项。导入同一个 Bangumi 条目时复用已有记录；系统不会通过相似标题自动合并不同版本，名称重复时提示核对。已关联 Bangumi 的作品仍可更新外部资料，也不会覆盖管理员编辑的作品文案。

管理员和超级管理员可在作品编辑区点击“删除书库作品”，确认后从公共书架与管理列表移除。该操作标记现有作品为 `catalogDeleted`，不会物理删除 `works` 行、帖子、个人书单、Tier 榜内容或活动记录；作品详情保留并显示已移出书库提示。删除校验最新角色、CSRF 和作品版本，并记录审计日志。普通用户不能重新收录被管理员删除的作品；管理员通过 Bangumi 收录或手动添加同一作品可恢复原编号。删除会清除其展示排序，重新收录后排在已排序作品之后。不需要数据库迁移。

添加作品或管理员从搜索结果收录新作品后，弹窗提供“继续添加”和“查看作品”。继续添加会清空上一部作品的表单及自选封面；关闭弹窗不会再次提交，添加页面保留成功结果和后续操作入口。恢复自选封面、下架公开 Tier 榜单前会先弹窗确认，取消不会修改数据。弹窗支持键盘操作、Escape 关闭及深浅色主题。

搜索结果命中已收录的 Bangumi 编号或规范化名称时，选择已有作品会弹窗提示“作品已收录”，可查看已有作品或继续查找。管理员导入被服务端复用已有记录、添加表单提交时发现书库已被其他用户补充的情况，也提供已有作品提示，不重复创建。

管理员可在书库管理中拖拽排序手柄，或使用上下移按钮、手柄上的方向键调整顺序，点击“保存排序”后对所有访客生效。筛选列表时暂不可排序；撤销只还原未保存的排序。服务端校验管理员权限、CSRF、完整公开作品集合及原顺序，书库有新增或其他管理员先保存时返回冲突，需重新加载后再调整。顺序保存在现有 `works.data.displayOrder` 中，无需新增表或迁移；作品 ID、历史十二橙器排名及编辑版本不变。新增作品排在现有已排序作品之后。

作品书架默认使用保存的书架顺序，也可切换收录顺序、Bangumi 评分或名称排序。会社筛选向所有访客开放，依据作品制作组资料生成选项和数量；联合署名按 `/`、`／`、`、`、分号拆分，可分别筛选。大小写、全角和空格差异会规范化；该功能不自动推断会社别名或母子公司。会社筛选可与文字搜索同时使用，卡片列表与立体书架使用相同结果。

## 两种榜单

共同投票榜由管理员设置分层及作品池，所有注册用户都可参与。每部作品每个账号只能选择一个分层；提交后统计各层人数，改票替换原选择，撤回后不再计数。支持只为部分作品投票。管理员的模板排列不计入选票。公开接口只提供分层人数统计，本人选票需要登录后单独读取。

个人榜由注册用户自行制作，从 Bangumi 搜索添加作品后安排各层。只有作者可以编辑或发布，其他用户及管理员不能修改其排列。管理员可下架违规个人榜；作者仍可保存草稿，恢复公开须管理员解除下架。个人榜单独展示作者，不接受共同投票。

个人榜添加的 Bangumi 作品不会自动进入公开书架；注册用户明确添加到书库，或管理员收录后，才会进入公共书库。原始条目资料可供榜单正常显示。

## 草稿与发布

保存草稿后，访客继续看到上次发布的版本；只有“发布当前版本”会更新公开内容。“下架公开榜单”隐藏公开版本并保留草稿。不同管理员同时编辑时使用版本校验，发生冲突需刷新后重新编辑。

分层颜色只接受六位十六进制颜色，最多 20 层、200 部作品，同一作品不能跨层重复出现。每部作品必须已经存在于本站书库。管理操作校验管理员权限、登录会话和 CSRF，并写入审计日志。普通用户可以贡献公共书库作品、维护自己添加作品的封面，并管理本人榜单及共同榜选票；共同榜设置和书库已有文案的编辑仍由管理员负责。

## 本地启动与上线更新

`tier_lists` 保存榜单草稿与公开版本；`tier_owners` 记录个人榜作者和下架状态，没有作者记录的旧榜单继续作为共同榜；`tier_ballots` 保存每个用户在共同榜上的最新选择和版本。原有 `works` 表继续保存作品 JSON，迁移不会删除已有数据。Windows 本地执行：

```powershell
pnpm.cmd db:migrate
pnpm.cmd dev:api
# 另一个终端
pnpm.cmd dev
```

宝塔部署时先备份数据库，更新当前代码并执行：

```bash
cd /www/wwwroot/galweb
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm --filter @chengzhixiang/api build
```

然后在宝塔重启 API 项目，再部署相同版本的 EdgeOne 前端。本地开发分支为 `codex/local-development`，上线分支需要在审核后再合并。

## 数据更新与账号注销

共同榜发布新作品池时，会清除已经移除的作品或分层对应的旧选择；后续重新添加不会恢复这些已清除的选票。保存草稿不改变投票作品池。提交携带公开版本标识及本人选票版本，拒绝旧模板与旧标签页覆盖。

被禁用账号的选择不计入公开统计。用户注销时清除其共同榜选票和个人榜；其他人的个人榜及共同榜继续保留。

## 外部接口与故障

后端仅请求固定的 `https://api.bgm.tv/v0`，不接收用户输入的上游地址。使用官方建议的可识别 User-Agent，游戏类型筛选为 `4`，单次请求超时 8 秒，相同查询缓存 5 分钟，并限制每个访问 IP 每分钟最多 30 次搜索。封面接受 `lain.bgm.tv` 的 HTTPS 封面及其 `/r/` 缩略图路径，加载失败时显示占位提示。

默认使用公开搜索和条目资料；后端可选配置个人访问令牌，尚不包含 Bangumi OAuth 或用户收藏同步。部分条目受 Bangumi 的账号权限和可见范围限制。服务器需要能访问 `api.bgm.tv:443` 和 `lain.bgm.tv:443`；上游超时、限流或不可用会显示错误，已导入作品仍可浏览。外部评分不是本站投票结果。

### 配置个人访问令牌

本机编辑 `D:\works\galweb\apps\api\.env`；宝塔编辑 `/www/wwwroot/galweb/apps/api/.env`，填入：

```dotenv
BANGUMI_ACCESS_TOKEN=你的原始令牌
```

只填写原始令牌，不加 `Bearer`、空格或换行。保存后重启 API：本机停止并重新运行 `pnpm.cmd dev:api`，宝塔在 Node 项目中重启 `galweb-api`。首次更新代码时先执行 `pnpm --filter @chengzhixiang/api build`，再重启。该配置不需要数据库迁移。

令牌仅由后端读取，不填写到 EdgeOne、`NUXT_PUBLIC_*` 或前端代码，也不要提交 `.env` 或在聊天中发送令牌。留空时继续提供公开搜索；撤销或替换令牌后需要重启 API。

本站用户登录后可在 Bangumi 搜索中勾选“包含受限条目”，再执行搜索。游客和未勾选的查询不携带令牌；授权查询与公开查询的缓存分开。勾选时按官方搜索规范发送 `nsfw: null`，同时包含公开与账号有权访问的受限条目。实际可见范围仍取决于 Bangumi 的账号权限和令牌有效期；无法保证所有条目都能返回。

已登录用户提交 Bangumi 作品、管理员导入或更新外部资料、个人 Tier 榜添加作品时，服务端可使用令牌取得条目详情。令牌不会转发到封面 CDN。导入后的资料沿用本站现有书库和榜单发布规则：添加到公共书库的资料会公开展示，搜索选项不等同于公共书库的内容隐藏设置。

上游返回 401/403 时，本站返回 Bangumi 授权不可用提示，不会将其当作本站登录过期。检查令牌是否过期或被撤销、账号是否具有条目访问权限；不要通过关闭证书校验解决授权问题。自动测试使用假令牌与隔离环境，不验证个人真实令牌。

参考 [Bangumi 官方授权说明](https://github.com/bangumi/api/blob/master/open-api/api.yml) 与[搜索接口规范](https://github.com/bangumi/server/blob/master/openapi/v0.yaml)。

Bangumi 封面经同源 `/api/bangumi/cover?image=…` 获取，用户浏览器无需直连图片站。接口只接受固定 CDN 的 HTTPS 封面路径，禁止重定向，限制大小、像素、并发与超时，并重新编码为 WebP。服务器缓存位于 `UPLOAD_DIR/.cache/bangumi-covers`，默认有效期 7 天，最多保留 256 张；上游暂时失败时可返回已有旧缓存。EdgeOne 仅为成功的无 Cookie 封面响应开启一天公共缓存，其他 API 继续禁止公共缓存。

部署用户（宝塔默认 `www`）需要写入上传目录；缓存自动创建，不需要新环境变量。此更新使用原 `works` JSON 字段，无需新增数据库表。前后端应一并更新并重启 API，再重新部署 EdgeOne。已有 Bangumi 封面地址无需重新导入。

此功能参考了 [VNFest 项目](https://github.com/kokubunshu/china-visualnovelcircle-maps) 的作品检索与榜单管理思路，在现有 Nuxt / NestJS 代码中独立实现。接口依据 [Bangumi 官方 v0 规范](https://github.com/bangumi/api/blob/master/open-api/v0.yaml) 和 [User-Agent 说明](https://github.com/bangumi/api/blob/master/docs-raw/user%20agent.md)。

提名窗口支持实时书库选择、Bangumi 搜索和手动填写。提交时可提供 `workId` 或 `subjectId`（两者互斥），名称和会社由服务端书库或 Bangumi 详情确认；不提供编号时按名称及别名匹配。已有作品复用编号，新作品随提名一并收录，记录添加人；收录和提名处于同一事务，配额不足等失败不会留下新条目。管理员已删除的作品不能通过提名恢复。候选项的 `coverRank` 对应书库作品编号，前端读取实时上传封面或 Bangumi 同源代理封面，提名审核规则保持不变。部署需同时更新前后端，无需数据库迁移；Bangumi 授权配置沿用上文。
